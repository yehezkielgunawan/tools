## Local Development

Install dependencies:

```bash
pnpm install
```

Start the development server at `http://localhost:3000`:

```bash
pnpm run dev
```

Run the local quality gates:

```bash
pnpm run check
pnpm run lint
pnpm run typecheck
pnpm run test
pnpm run build
```

Preview the production build locally:

```bash
pnpm run preview
```

## Routes

- `/` - available tools
- `/generator/whatsapp-link` - WhatsApp link generator
- `/generator/greeting-card` - personalized greeting cards with live previews and PNG downloads
- `/generator/invoice` - local invoice editor with autosaved drafts, PDF downloads, and read-only share links
- `/developer/json-formatter` - JSON formatter
- `/pdf/pdf-editor` - local PDF editor for text, pen, and drawn signatures
- `/pdf/pdf-images` - convert PDF pages to PNG/JPEG, or assemble images into a PDF
- `/image/powerpoint-images` - convert PPTX slides to PNG/JPEG, or assemble images into a PowerPoint deck
- `/changelog` - release history and notable changes

Unknown routes show a 404 page. Tool modules are lazy-loaded so new tools do not need to be included in the initial route bundle.

## Release Process

The repository uses Semantic Versioning, Conventional Commits, and Release Please for one application version across all tools.

Use a Conventional Commit-style pull request title so the release history can be generated automatically:

```text
feat(json): add tree view
fix(whatsapp): encode emoji correctly
perf(image): reduce memory usage
feat(config)!: replace the legacy configuration
```

Use stable tool or product-area scopes such as `whatsapp`, `json`, `image`, `pwa`, `ui`, `seo`, `build`, or `release`. Pull requests are expected to use squash merge so the validated title becomes the release commit message.

Release Please opens a release pull request after releasable commits reach `main`. Merging that pull request updates `package.json`, `CHANGELOG.md`, and the release manifest, then creates a `vX.Y.Z` tag and GitHub Release. Released changelog sections should not normally be edited manually.

The `RELEASE_PLEASE_TOKEN` repository secret is a fine-grained token restricted to this repository with Actions read-only, Contents read/write, Issues read/write, and Pull requests read/write permissions. If it expires, replace the secret value; the workflow does not need to change.

Production deployment remains manual through `workflow_dispatch` in `.github/workflows/deploy.yml`.

## Social Metadata

The homepage emits the default SEO and Open Graph tags at build time. The Worker rewrites those tags for every registered tool route before serving the SPA shell, so social crawlers receive the correct title, description, canonical URL, and image without running React.

OG images are generated by [og-image-rev](https://og-image-rev.yehezgun.com/) and use the public square logo at `/yehezgun-tools-og-logo.png`. The build regenerates that logo from the favicon with `pnpm run generate:og-logo`. Adding a tool to `src/tools/registry.ts` automatically gives it route-specific metadata and an OG image.

## Privacy

The WhatsApp Link Generator, JSON Formatter, Image Compressor, and PDF Editor run in the browser. PDF files, signatures, and edits are not sent to an application server or external API. The PDF editor keeps a document in memory for the current session and downloads a new edited copy; it does not save drafts between sessions. A drawn signature is a visual mark, not a cryptographic digital signature.

The Greeting Card Generator sends card text and design settings to `https://og-image-rev.yehezgun.com/cards/render`. The service renders cards on demand without saving them in a database. Preview requests are debounced, and downloads reuse the current preview PNG. Rendering requires an internet connection; drafts and generated cards are held only in memory for the current session.

The Invoice Generator calculates totals and generates PDFs locally. It autosaves one draft in LocalStorage on the current browser. **Clear saved invoice data** removes this tool's draft and resets the editor without changing other tools' storage. A shared invoice is a snapshot encoded in the URL fragment, which is not sent to the server. Anyone with the complete link can read its contents; clearing the local draft does not revoke previously shared links. Shared views do not overwrite the local draft unless **Make a copy** is chosen and replacement is confirmed.

Invoices support up to 100 line items, fractional quantities, an invoice-wide fixed discount applied before tax, and a single tax percentage. Share URLs are limited to 8,000 characters; larger invoices can still be downloaded as PDFs. PDF export uses locally bundled Noto Sans fonts for Latin, Greek, and Cyrillic text and reports unsupported characters instead of dropping them. The live preview supports browser text rendering and may display characters that the PDF font does not support.

## PDF and PowerPoint ↔ Images

Both converters process files in the browser without uploads, external media requests, or third-party font requests. Files and results are kept in memory for the current tab; clearing the tool or leaving it releases its previews and downloads.

- **Document to images:** select all pages/slides or enter ranges such as `1-3, 5`. Choose PNG or JPEG and a longest edge of 1024, 1600, 2048, or 3072 pixels. Download individual images or prepare a ZIP. PDF rotation and source aspect ratios are preserved. Image exports use a white background.
- **Images to PDF:** add JPEG/PNG images, reorder them, and create one page per image. Choose A4, US Letter, or proportional image-sized pages, with orientation, margins, and fit/crop controls. Transparent images are placed on white pages.
- **Images to PowerPoint:** create one image per slide in a 16:9 or 4:3 PPTX, with fit/crop controls and white slide backgrounds. Text remains part of each image rather than becoming editable PowerPoint text.
- **PPTX rendering:** static and best-effort. Missing fonts use local fallbacks. Complex layouts, charts, SmartArt, and effects may differ or be omitted; animations, video playback, and legacy `.ppt` imports are not supported. Review the rendered previews before downloading.

Limits: 32 MiB per document, 50 selected output pages/slides or input images, 64 MiB combined image inputs, and 128 MiB retained results. Image inputs also follow the existing 24-megapixel validation limit and are normalized to a maximum 3072-pixel edge when creating documents. PPTX archives are limited to 4096 entries, 32 MiB per expanded entry, and 128 MiB total expanded data. Cancellation takes effect at the next supported processing boundary; ZIP creation and active PDF renders are interruptible.

PowerPoint import requires a modern browser with `DecompressionStream('deflate-raw')` support. The converters work offline after the production service worker has cached the app and conversion assets.

The pinned PowerPoint dependencies have reproducible pnpm patches in `patches/`. The `pptx-browser` patch disables automatic Google Fonts loading, bounds archive expansion, fixes text color/run handling, and releases image URLs. The `pptxgenjs` patch removes `node:` prefixes from optional server imports so its existing browser exclusions work in the production bundler. Recheck these patches and `tests/pptx-local-renderer.test.ts` when upgrading either package.

## Progressive Web App

Production builds emit an installable web app manifest and a Workbox service worker. The application shell, fonts, icons, and registered tool bundles are precached so the current tools remain available offline after the first successful load. When a new deployment is available, the app offers a refresh prompt instead of reloading while a tool is in use.

The Greeting Card Generator's editor can load offline, but previews and PNG generation require its external rendering service. Rendering requests and card images are not cached by the service worker.

## Deployment

The application is configured for Cloudflare Workers Static Assets in `wrangler.jsonc`.

The deployment workflow is intentionally manual and only runs when dispatched from the `main` branch. It runs all quality gates, builds `dist`, and deploys the assets with Wrangler.

Configure these GitHub repository secrets before dispatching `.github/workflows/deploy.yml`:

- `CLOUDFLARE_ACCOUNT_ID`
- `CLOUDFLARE_API_TOKEN`

The Wrangler configuration enables SPA fallback for direct route refreshes, runs the metadata Worker first for document routes, and maps the Worker to `tools.yehezgun.com` as a custom domain. The Cloudflare zone and DNS record must be available in the account before the first deployment.
